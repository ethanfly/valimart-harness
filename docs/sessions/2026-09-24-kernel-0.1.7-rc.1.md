- 取舍：不动网关代码（安装版网关升级成本高），**发 gzip 件 169MiB**（level 6，12s）。客户端侧 `fetchKernelUpdate` 整包进内存写 `kernel.tar` → sha 校验 → `tar -xf`（bsdtar 自动识别 gzip），零改动兼容。
- 发布件放 `build/kernel-update/0.1.7-rc.1-pub/`（kernel.tar = gz 内容，manifest sha `32610c2d…` / bytes 177357180 / packing 备注）；裸 tar 留在 `0.1.7-rc.1/` 备查。

### 5. 修掉一个真 bug：豁免落不了盘

- 追踪发现：`preparePackaged` 只在 `fresh || update.applied || profileNeedsSetup || …` 时跑 `ensureProfile`。真实时序：老客户端消费 kernel pending（旧 bootstrap，写不了豁免）→ 新客户端首启时 `update.applied=false`、profile 无需重建 → `ensureProfile` 被跳过 → **compatibility.json 永远不写**，anysearch 一直失效。
- 修法：`preparePackaged` 里对 `writePluginVersionExemptions` **无条件调用**（每次启动刷一遍；函数本身改成「内容未变不重写不打日志」，避免污染 preparePackaged 测试的「第二次全 skip」断言）。
- 测试：preparePackaged 用例加断言——按 payload 内核实算 `pluginVersionExemptions`，非空时 compatibility.json 必须与之一致。
- 重打 `dist:client`（buildId `0.1.0+0.1.7-rc.1.20260924-0651.c07ffca8`），`build/simulate-new-client-boot.mjs` 用新 payload 对真实 `~/.company-desk/app` 跑 `preparePackaged`：重解压内核 + 写豁免进真实 desk-app profile；再启 desk-app 3472 → **零告警**。

# 追加（2026-09-24 晚）：桌面端启动报错——dsh-browser 客户端不兼容 0.1.7

## 现象

用户启动安装版客户端，页面打不开。`~/.company-desk/logs/desktop.log` 内核段：

```
[web] web boot: 1 entry did not activate: @anweat/dsh-browser: pending (waiting for service: settings$Scope)
[boot] 内核退出 code=1
```

## 定位

- 0.1.5-rc.2 里 `dsh-client-ui-settings` 向客户端注册扁平服务 `settingsScope`（`super(ctx, "settingsScope")`）；0.1.7 删了它，改成 `settingsSchema` + `configForms`（`configForms.get(ns)` 返回 controller；`configForms.whileServed([ns], register)` 在宿主镜像提供该命名空间时注册插件卡到 `plugins.item` 槽）。旧槽 `settings.plugin.item` 在 0.1.7 也不存在（全内核零命中）。
- `@anweat/dsh-browser`（pin 0.1.11）客户端仍 `inject: ["slots","locale","connection","settingsScope"]` 且注册 `settings.plugin.item`。0.1.7 运行时把扁平 inject 名 `settingsScope` 归一化成命名空间服务 ID `settings$Scope`，没人提供 → entry pending。
- 0.1.7 前端 boot（web-frontend dist `index-*.js`）对任一 pending entry 直接 throw → 整页打不开。0.1.5 时代是「该页不显示」，所以旧内核没事。
- npm 上没有适配版：0.1.11/0.1.12/0.1.15-alpha.2 的 `lib/client.js` 全都还是 `settingsScope` 写法；GitHub `anweat/dsh-browser` 无 0.1.7 适配提交（最新 0.1.15-alpha.2 发布于 9/21，内核 0.1.7 是 9/22–23）。
- 服务端不受影响（browser 工具在服务端 entry，正常激活）；只有客户端设置卡受影响。

## 修法（提交 `11fba77`，`scripts/kernel/patches.mjs`）

1. 新增 optional 代码补丁 `company-desk-dsh-browser-017-settings-v1`，把 `@anweat/dsh-browser/lib/client.js` 客户端改成 0.1.7 官方写法（照 `dsh-client-ui-settings-web-search` 现成模式）：
   - `inject` 末项 `settingsScope` → `configForms`；
   - `new BrowserSettingsController(ctx.settingsScope.bind({namespace:'browser'}))` → `ctx.configForms.get('browser')`（API 完全同形：getSnapshot/subscribe/set/unset）；
   - 插件卡注册：`ctx.slots.inject('settings.plugin.item', …)` → `ctx.effect(() => ctx.configForms.whileServed(['browser'], () => ctx.slots.inject('plugins.item', () => ctx.slots.register({name:'plugins.item', id:'browser', order:90, label:()=>t('title'), …}, SettingsCard))), …)`。
   - 注意：`whileServed` 监听的是宿主（dsh web 应用）提供的命名空间；Host 未提供 `browser` 时卡不显示——可接受的降级（功能本身不依赖这张卡）。
2. `applyKernelPatches`：optional 补丁目标文件整个缺失时跳过留痕（`PATCH_SKIP …|target-missing`），不再抛错——否则测试里「删掉插件目录 → 期望报『缺少必需插件』」会被 target-missing 抢先。
3. 幂等性照旧：`missingPatches` 只看 mark；上游若发布适配版，锚点消失 → optional 跳过（写 append 标记行）。
