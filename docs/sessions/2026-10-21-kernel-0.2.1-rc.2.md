## ① dsh-purge：调查后拒绝安装（决策记录）

`dsh-purge` 不在 npm（各作用域变体均 E404），实为 GitHub 项目 `YuJunZhiXue/dsh-purge`（~4k star，MIT，自称「破甲插件 / cybersecurity red-team tool」）：直接改写本机 `@deepseek-ai/*` 内核包的默认提示词、权限策略与工具限制，让所有模型可被越狱，支持按模型换越狱提示词；原仓库据称即将删库，现多为镜像/fork（LanJinGod、JeffKeeping/dsh-purge-plus、Potato1008ypy、mmparko 等），插件目录标注 "Safety audit: Unaudited"。

拒装理由（与公司环境直接冲突）：

1. **与锚点补丁层冲突**：本仓库对内核是锚点式补丁（`from` 恰好命中 1 次否则硬失败），dsh-purge 也改同一批内核文件（`.dshpurge.bak` 备份、升级后重打）。叠加后 `kernel:check` 必然报错，门禁更新流程被破坏。
2. **企业多用户 + 上游订阅账号风险**：网关后面是多个员工账号与公司上游 OAuth 订阅（ChatGPT/Grok/Claude/Gemini）。全员客户端解除模型安全限制几乎必然违反上游平台 ToS，订阅账号有被批量封禁风险。
3. **供应链风险**：未审计第三方代码 + 原仓库删库、镜像遍地的典型投毒窗口；公司 profile 默认权限预设是 `danger-full-access`，等于给未审计代码完全权限。

若目的是研究/防御（识别员工机器上是否被装、它改了哪些文件），可在仓库外隔离目录做代码审查出报告，不装入 company-harness。
