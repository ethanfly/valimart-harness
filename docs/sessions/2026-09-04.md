## 踩过的坑与修法

| 现象 | 原因 | 修法 |
|---|---|---|
| 网关重启后发消息报 `API key is invalid` | 令牌策略是「一人一枚」：管理页 / 第二台电脑一登录就把旧令牌作废，而心跳查的是「这个人有没有任意有效令牌」，查不出来 | 令牌绑定登录会话；管理页登录 `gatewayToken: false`；心跳查「本机这枚」；失效即弹登录遮罩 |
| 首页仍是官方「探索未至之境 · 预览版」 | `dsh-client-ui-conversation` 写死标题与徽标，`ui-brand-official` 又占了槽 | 往 `conversation.hero.brand.mark` 槽注册 `HeroWordmark`，CSS 隐藏官方标题与徽标 |
| 侧栏出现两个「个人」 | 同一台电脑多人登录过，各自的个人工作区都留在列表 | `ensureWorkspaces` 收起非当前登录者的 `_office/*` 工作区（目录保留） |
| 设置 → 订阅 空白 | `useMemo` 写在条件 `return` 之后，hooks 顺序错 | hooks 提到函数顶部 |
| 人员表格溢出 | 长内容 + 固定宽度按钮 | `dk-table-wrap` 横向滚动、`nowrap`、加宽设置弹窗 |
| 浏览器自动化往 ProseMirror 输入得到 `undefined` | `browser_fill` 不适合 contenteditable | CDP `Runtime.evaluate` 走 `execCommand('insertText')` |
| 截图尺寸不听 `setDeviceMetricsOverride` | 默认截可视区 | `Page.captureScreenshot` 带 `clip` |

### 踩过的坑与修法

| 现象 | 原因 | 修法 |
|---|---|---|
| `npm --prefix desktop install --allow-scripts=electron` 报 `EALLOWSCRIPTS` | npm 11.19 的 `--allow-scripts` 只给 `npm exec` / 全局安装用，项目内要走 `allowScripts` 字段；而 Electron 44.1.1 根本没有 postinstall（二进制首次 `electron .` 时惰性下载） | 直接 `npm --prefix desktop install`；计划 / 脚本提示里的 flag 删掉 |
| Electron 二进制从 GitHub 下载 217 s 后 `TypeError: terminated`，一个字节没下到 | 这个网络到 GitHub Releases 的 HTTP/2 流被掐 | `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 13.8 s 完成；electron-builder 的 NSIS / 7zip / icons 同理走 `ELECTRON_BUILDER_BINARIES_MIRROR`；`build-client-installer.mjs` 在未设置时默认这两个镜像 |
| 内核前缀 3 万个文件、最长相对路径 190 字符，担心 MAX_PATH | 解压器要处理长路径；PowerShell 5.1 的 `Get-ChildItem -Recurse` 在 >260 字符路径上报错（是 PS 的限制，不是 tar 的） | 单个 `kernel.tar` 随包，解到短路径 `~/.company-desk/app/kernel`；用 154 字符的基路径实测 bsdtar 解压正常，不必自写 tar 读取器；修剪 `.d.ts` / map / 其他平台预编译后 29,611 → 14,352 个文件 |
| `kernel.tar` 里带着构建机的绝对路径（戳记 `skillsDir`、预设 yaml 里的技能根） | 整个前缀原样打包；`missingPatches` 只看 mark 看不出路径不对 | `pinSkillsRoot`：比戳记里的 `skillsDir`，不一致就在客户机重跑 `applyKernelPatches` 同步技能根并重写戳记（构建机 = 客户机时 skip 是正常的） |
| 客户端装到了 `%LOCALAPPDATA%\Programs\the-diva-desktop`，不是设计的 `Programs\THE DIVA` | electron-builder 26 在 oneClick + 按用户模式下有意用包名（`APP_FILENAME`）作目录，yml 无选项可改 | 接受实际目录（快捷方式 / 卸载项仍是「THE DIVA」），改文档措辞 |
| Task 8 找不到 makensis | 计划写的缓存路径 `Cache\nsis\…` 不对，实际是 `Cache\nsis-3.0.4.1\nsis-3.0.4.1-<随机后缀>\Bin\makensis.exe`；同级还有一个 2.5 KB 的壳 `makensis.exe` | `findMakensis()` 遍历 `Cache\nsis-<数字>*\*\Bin\makensis.exe`，`MAKENSIS` 环境变量优先，最后才 PATH |
| `desktop/build/icon.*` 无法 `git add` | `.gitignore` 的 `build/` 匹配任意层级 | 改成 `/build/`（只忽略根目录的 build/） |
| Electron 的 userData 落在 `%APPDATA%\THE DIVA` | Electron 默认行为，不在「运行期状态只在三处」的约束里 | `app.setPath('userData' / 'sessionData', <appDir>/electron)`，在单实例锁之前 |
| 关掉启动页会留下 bootstrap / 内核孤儿；`runBootstrap` 用 `exit` 判定可能丢最后一行 | Electron 退出路径没杀 bootstrap 子进程；`exit` 时 stdio 可能没读完 | `quitting` 检查、退出时 `killTree` bootstrap 与内核；改用 `close` 事件并解析无换行的尾行 |
| `preparePackaged` 的 `rmSync(appDir)` 会删整个目录；网关卸载器 `RMDir /r $INSTDIR` | `--app-dir` / 安装目录若被指到已有目录会被整个清空 | 只删自己创建的条目（`APP_DIR_ENTRIES`）；卸载器只删 `runtime\ server\ service\ README.txt Uninstall.exe`，最后非递归 `RMDir` |
| 网关 README 教人往服务 XML 里加 `<env>` 放密钥 | XML 每次安装 / 升级都由 `init.mjs` 重生成，手改会丢 | 改成三种跨升级可保留的方式：客户端通道接入 / `config.local.json` 的 `upstreams.<id>.apiKey` / 机器级 `DEEPSEEK_API_KEY` |
| PowerShell 5.1 里 `a && b` 语法错误；`-m "中文"` 提交信息乱码；控制台里 `→`、中文显示成 `?` | PS 5.1 无 `&&`；控制台默认 GBK 代码页 | 多条命令用 `;`；提交信息写进 UTF-8（无 BOM）文件后 `git commit -F`；文件 / 产物本身校验过都是正确的 UTF-8 |
